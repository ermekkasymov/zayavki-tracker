# PRD: Трекер контроля заявок

## 1. Проблема

Заявки поступают ежедневно и обрабатываются вручную в блокноте. Нет единого места, где видно:
- на каком этапе находится каждая заявка;
- кто заказчик и какому поставщику она передана в работу;
- сколько дней заявка «висит» на текущем статусе;
- сколько заявок просрочено и требует внимания.

Ручное ведение в блокноте не масштабируется, не даёт сводной картины и не напоминает о забытых шагах.

## 2. Цель

Дать удобный, ежедневно используемый инструмент для контроля статуса заявок: единая таблица, выпадающие списки вместо ручного ввода, автоматические напоминания и наглядная сводка по нагрузке.

## 3. Пользователь

Один основной пользователь — менеджер, который:
- ежедневно заводит новые заявки;
- меняет статус заявки по мере продвижения по этапам;
- периодически смотрит сводку, сколько заявок и на каком этапе.

## 4. Формат решения

Файл Excel (.xlsx), три листа: **Заявки**, **Справочники**, **Сводка**. Редактируется вручную, без необходимости в стороннем ПО кроме Excel.

## 5. Функциональные требования

### 5.1 Лист «Заявки» (основной)
| Поле | Тип | Комментарий |
|---|---|---|
| № | авто | номер строки, проставляется формулой |
| Дата поступления | дата | вводится вручную |
| Заказчик | выпадающий список | 10 значений из справочника |
| Поставщик | выпадающий список | 3 значения из справочника |
| Текущий статус | выпадающий список | 5 значений: Принято в работу / Запрос цены / Отправлено предложение / На согласовании у Заказчика / Отправлено |
| Дата по каждому статусу | дата, 5 колонок | по одной колонке на каждый статус, вводится вручную при переходе |
| Дней на текущем статусе | авто | `сегодня − последняя проставленная дата статуса` |
| Комментарий | текст | свободное поле |

Требования к поведению:
- Статус выбирается из списка, не вводится вручную (защита от опечаток).
- Цветовая индикация строки/ячейки статуса — свой цвет на каждый статус.
- Если статус выбран, а дата для него не проставлена — ячейка даты подсвечивается жёлтым (напоминание).
- Если заявка находится на статусе дольше порога просрочки — колонка «Дней на статусе» подсвечивается красным.
- Заявки со статусом «Отправлено» (закрытые) — строка визуально «гаснет» (серый цвет, приглушённый шрифт).
- Автофильтр по всем колонкам, закреплённая шапка.
- Запас в 100 строк на старте, стили тянутся заранее — не нужно форматировать при добавлении новой заявки.

### 5.2 Лист «Справочники»
- Редактируемые списки: Заказчики (10), Поставщики (3), Статусы (5).
- Изменение значения в справочнике автоматически обновляет выпадающий список на листе «Заявки» (именованные диапазоны).
- Настраиваемый порог просрочки (в днях) — влияет на подсветку на листе «Заявки».

### 5.3 Лист «Сводка»
- Количество заявок по каждому статусу (авторасчёт).
- Общее количество заявок.
- Количество просроченных заявок.
- Столбчатая диаграмма распределения заявок по статусам.

## 6. Нефункциональные требования
- Ноль ошибок формул (#REF!, #DIV/0! и т.п.).
- Шрифт Arial везде, единый визуальный стиль.
- Файл открывается и полностью работает в десктопном Excel без макросов и надстроек.
- Редактирование одной заявки — не более 2–3 кликов (выбор из списка + дата).

## 7. Вне рамок текущей версии
- Полностью автоматическое проставление даты статуса без ручного ввода (требует VBA-макроса).
- Форма быстрого ввода заявки (отдельное окно ввода).
- Зависимые списки поставщиков от выбранного заказчика.
- Автоматическая архивация закрытых заявок на отдельный лист.
- Веб/мобильная версия (канбан-доска в браузере) — рассматривалась как альтернативный вариант реализации.

## 8. Возможные следующие шаги
1. VBA-макрос для автопроставления даты статуса по клику.
2. Автоматический перенос закрытых заявок в архив.
3. Интерактивная веб-версия (канбан-доска) как альтернатива или дополнение к Excel-файлу.

## 9. Метрика успеха
Пользователь полностью отказывается от блокнота и ведёт 100% заявок в файле; просроченные заявки выявляются в день просрочки, а не постфактум.
